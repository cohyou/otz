# 数学的モデル：スキーマ、インスタンス、クエリ

> ステータス: 基本モデルは採用方針。固定 type-side と symbolic frozen instance の精密な対応付けは未解決。

## 1. スキーマとインスタンス

エンティティのスキーマ圏を $C$ とし、単純化した集合値インスタンスを

$$
I:C\longrightarrow\mathbf{Set}
$$

で表す。実際の Algebraic Databases では、type-side の理論と代数、エンティティ・外部キー・属性、スキーマ等式を区別する。固定の type-side 代数 $A$ に対する属性付きインスタンスの圏を $S\text{-Inst}_A$ と記す。

- **採用方針**: type-side の代数を固定する。プログラミング言語の値型の定義のように、実行時のアクションで変更しない。
- **採用方針**: インスタンスの構文表示はエンティティ生成元の context と等式で考える。
- **注意**: $I:C\to\mathbf{Set}$ は簡略表記。属性・型付き項の詳細を省略した式で全構造を説明したことにはならない。

## 2. 等式と事実

スキーマ等式は全インスタンスが満たすべき規則。インスタンス中の等式はその状態の個別事実を表現する。この二つを区別する。

エンティティが存在すること、属性や外部キーが特定の値を持つことは状態の一部になる。式 $a_1.\mathrm{task}=t_1$ などを状態中の事実として扱う構想と整合する。

等式の導出、同値類（商）による表現、関数値の置換は別の問題である。

## 3. Frozen instance クエリ

基本クエリを

$$
Q=(\Gamma_Q,\Phi_Q)
$$

と書く。$\Gamma_Q$ は型付き変数 context、$\Phi_Q$ は等式の連言。型付き自由項から等式で商を取った frozen instance を

$$
F_Q=\langle\Gamma_Q\rangle / E_Q
$$

と表す。インスタンス $I$ における解（証人／マッチ）は適切なインスタンス圏での準同型に対応する：

$$
\operatorname{Sol}(Q,I)\cong
\operatorname{Hom}_{S\text{-Inst}_A}(F_Q,I)
$$

この解釈は **等式連言クエリ** の基本範囲についてのもの。任意の否定・選言・量化・再帰をこの式だけで表現したことにはならない。

$frozen\ instance$ の自由な記号項と、実行時に固定した具体 type-side 代数 $A$ の値の関係には追加の仕様が必要。非自明なタイプ理論を使う場合、単純な $F_Q$ の構成をそのまま適用できるとは限らない。

## 4. WHERE と RETURN

- `WHERE` はマッチが満たす等式条件を規定する。
- `RETURN` は解から何を取り出すかを指定する射影で、準同型そのものとは区別する。
- 更新では **真偽値だけでなくマッチ $m$ 自体** が必要。例えば対象のエンティティの ID をマッチから取得する。

クエリが成立する条件は

$$
\operatorname{Hom}(F_Q,I)\neq\varnothing
$$

である。ゴールクエリ $G$ を用いた成功状態集合は

$$
W_G=\{w\in W\mid\operatorname{Hom}(F_G,I_w)\neq\varnothing\}
$$

となる。

## 5. Doctrine との位置付け（研究仮説）

固定スキーマ $S$ の型付き context 圏 $\mathcal C_S$ 上に、等式から生成される述語の doctrine

$$
P_S:\mathcal C_S^{op}\longrightarrow\mathbf{Pos}
$$

を考える。実存量化や全称量化を追加する場合の随伴と、代入に対する整合性（Beck–Chevalley など）は追加条件。

異なるスキーマにまたがる場合、単一の Hyperdoctrine にスキーマを押し込む代わりに、$S\mapsto P_S$ のようなスキーマ添字付きの doctrine、またはインスタンス圏の反変擬関手 $S\mapsto S\text{-Inst}$ と Grothendieck 構成を考える案がある。**実装の必須要件ではない**。

## 6. 重点検証事項

1. frozen instance の生成と type-side の定数・演算子の評価を混同しない。
2. インスタンス商に対する関数値更新が well-defined か。
3. エンティティの ID と数学的に観測可能なインスタンス同型を区別する。
4. マッチングを有限問題で網羅的に検証し、非単射マッチングもサポートする。
5. Query の同値性・射影の正しさ・後続更新への証人の引き渡しを検証する。
