# ADR-0005: マッチの行き先は生成元に限り、全域で有限なインスタンスを前提とする

- 状態: MVP 提案仕様
- 日付: 2026-11-23（C-03 の実装 #13 で決定）

## Context

$\operatorname{Hom}(F_Q, I)$ の準同型は、$F_Q$ の各変数を $I$ の要素に移す。$I$ の要素には、`#elem` で宣言した生成元（`e1`、`d2` など）だけでなく、`wrk(e7)` のような項（の同値類）も含まれる。

すべての項を行き先の候補にすると、候補が無限になり得る。一方、生成元だけを候補にすると、生成元に等しくならない項がある場合に、マッチを取りこぼす。

## Decision

- `eval::matches` は、変数の行き先を**型の合う生成元**（`Instance.elems` の `Elem::Oper`）に限る。
- MVP では、**すべての外部キーの値が生成元に正規化される**（全域で有限なインスタンスである）ことを前提とする。この前提のもとでは、生成元だけを候補にしても `Hom(F_Q, I)` を取りこぼさない。
- 前提は実行時に検査する（#17、バックログ B-02）。
- type-side の値（`Int` 型の変数など）を行き先にするマッチは、まだ扱わない（バックログ C-04）。

## Consequences

- マッチの候補は有限になり、直積で列挙できる。
- 前提を満たさないインスタンスでは、マッチを取りこぼし得る。検査（#17）が入るまでは、利用者が前提を守る必要がある。
- 属性（type-side の値）の全域性をどこまで要求するかは未決（例: サンプルの `last(e7)` は値が無い）。#17 で決める。
- 生成元に正規化されない項を行き先にするマッチ（labeled null を含む一般の場合）は、研究課題として残る。
