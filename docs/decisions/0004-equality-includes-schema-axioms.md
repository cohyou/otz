# ADR-0004: インスタンスの等しさにスキーマの公理を含める

- 状態: 採用方針
- 日付: 2026-11-23（C-03 の実装 #13 で決定）

## Context

クエリの `#where` の等式が成り立つかを判定するには、「インスタンスで成り立つ等式」の範囲を決める必要がある。候補は次の 2 つ。

1. インスタンスのデータの等式（`#data`）だけから導けるもの
2. データの等式と、スキーマの公理（`constraints`、例: `wrk(mgr(e)) = wrk(e)`）から導けるもの

Algebraic Databases（CQL）では、インスタンスの意味は 2（公理とデータから生成される代数）であり、クエリの解 $\operatorname{Hom}(F_Q, I)$ もその上で定義される。

修正前の `Instance::deducible` は、どちらでもなかった。判定する等式の左辺の型でデータを絞り込み、公理も使っていなかったため、`wrk!mgr!e = d2` のように途中で別の型の等式が必要な条件で、マッチを取りこぼしていた。

## Decision

- インスタンスの等しさは、**データの等式とスキーマの公理をまとめて補完した書換え規則**で判定する（`Instance::equality_rules`、`Equation::holds_under`）。
- 補完は `matches` / `eval` の呼び出しごとに一度だけ行い、すべての判定で使い回す。
- 向き付けできない等式は保留する（PR #8 の方針）。その場合、判定は健全だが不完全になり得る（正規形が一致すれば等しいが、一致しなくても等しくないとは言えない）。

## Consequences

- `Hom(F_Q, I)` に忠実になる。例えばサンプルのデータでは、`wrk` のデータが無い e7 も、`wrk(e7) = wrk(mgr(e6)) = wrk(e6) = d2` が導けるので `wrk!e = d2` にマッチする。
- アクションの前提条件やゴールでも、「直接書いていない事実が、公理から導ければ条件を満たす」ことになる。PDDL の閉世界仮定とは異なる。プランニングでの影響は #19 で確かめる。
- 補完が停止する保証はない（一般に決定不能）。#16 で、補完に決定的な上限（`CompletionLimits`: ステップ数、規則の数、規則の項の大きさ）を設け、超えたら `CompletionError` を返すようにした。`equality_rules`・`matches`・`eval` は `Result` を返す。
- プランニングでは状態ごとに補完が走るのでコストが大きい。公理の事前補完・合同閉包への移行・差分更新は未対応（research-roadmap R1-a も参照）。
